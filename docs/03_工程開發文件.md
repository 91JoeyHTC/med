## 1. 系統架構

```
                ┌─────────────────────────┐
   使用者瀏覽器  │  React + Tailwind (Vite) │  ← Vercel 靜態託管 + Edge
                └───────────┬─────────────┘
                            │ HTTPS / JWT (Supabase session)
              ┌─────────────▼──────────────┐
              │      NestJS API Gateway     │  ← Render/Railway/Fly
              │  Auth 驗證 · 盤面 CRUD · BFF │
              └───────┬───────────┬─────────┘
                      │           │ REST
          Supabase JS │           ▼
              ┌────────▼───────┐  ┌──────────────────────┐
              │   Supabase     │  │  Python FastAPI 服務   │
              │ Postgres/Auth/ │  │ 藥輪計算引擎 + 解析(LLM)│
              │   Storage      │  └──────────────────────┘
              └────────────────┘
```

**職責切分**
- **React**：UI、盤面 SVG 繪製、表單、即時繪盤（純前端可算本命，減少往返）。
- **NestJS**：對外 API、驗證 Supabase JWT、盤面 CRUD、彙整呼叫 Python 服務（BFF）。
- **Python（FastAPI）**：藥輪計算「真理來源」（生日→本命、家族平衡、相合）、解析報告（規則＋LLM）。前端與 NestJS 皆以此為準。
- **Supabase**：DB、Auth、檔案（匯出圖）。
- **Vercel/GitHub**：前端部署與 CI；後端容器化部署。

> 設計取捨：計算邏輯**同時存在於前端（即時體驗）與 Python（權威/解析）**，兩者共用同一份 JSON 規格資料（`medicine-wheel-spec.json`，見 §6），確保一致；測試以 Python 為基準金標。

## 3. 資料模型（領域）

### 3.1 位置（Position）型別
```ts
type Layer = 'center'|'sky'|'family'|'direction'|'moon'|'path';
type Element = '火'|'土'|'風'|'水';
type Family  = '雷鳥'|'海龜'|'蝴蝶'|'青蛙';
type Dir     = '北'|'東'|'南'|'西';

interface Position {
  id: number;            // 1..36
  layer: Layer;
  name: string;          // 顯示名
  // moon only:
  dateRange?: [number,number,number,number]; // [m0,d0,m1,d1]
  zodiac?: string; element?: Element; family?: Family; direction?: Dir;
  northAnimal?: string; twAnimal?: string;
  // path only:
  pathDir?: Dir; pathName?: string;
}
```

### 3.2 家族 ↔ 元素 ↔ 節點
```
雷鳥=火=node7 · 海龜=土=node5 · 蝴蝶=風=node6? 
```
> 注意：家族節點編號為 5 海龜 / 6 青蛙 / 7 雷鳥 / 8 蝴蝶。元素對應：海龜土、青蛙水、雷鳥火、蝴蝶風。
```ts
const FAMILY_NODE = { 海龜:5, 青蛙:6, 雷鳥:7, 蝴蝶:8 };
const DIR_NODE    = { 北:9, 東:10, 南:11, 西:12 };
const FAMILY_OF_ELEMENT = { 火:'雷鳥', 土:'海龜', 風:'蝴蝶', 水:'青蛙' };
```

### 3.3 相合規則
```
同族         : A.family === B.family            → 加乘
雙合(對立)    : 火↔風, 土↔水                      → 互補張力大
半合(相鄰)    : 其餘組合                          → 需磨合
（藥輪不採二元對立，無「絕對不合」）
```

### 3.4 盤（Chart）
```ts
interface Guardian { dir: '天'|'地'|'北'|'東'|'南'|'西'; animal: string; positions: number[]; }
interface Natal { monthId:number; familyNode:number; dirNode:number; zodiac:string; element:Element; family:Family; }
interface PersonChart { nickname:string; birth:{month:number;day:number}; natal:Natal; guardians:Guardian[]; }
interface Chart { id:string; ownerId:string; type:'personal'|'composite'; people:PersonChart[]; createdAt:string; }
```

## 4. 核心演算法

### 4.1 生日 → 本命月份（含跨年）
```ts
function natalMonth(month:number, day:number): Position {
  return MOONS.find(m => {
    const [m0,d0,m1,d1] = m.dateRange!;
    const after  = month> m0 || (month===m0 && day>=d0);
    const before = month< m1 || (month===m1 && day<=d1);
    return m0<=m1 ? (after && before)   // 同年區間
                  : (after || before);  // 跨年區間 (如 12/22–1/19)
  })!;
}
```
由本命月份取 `element → family → familyNode`，`direction → dirNode`，得本命三點 {monthId, familyNode, dirNode}。
**金標測試**：邊界日（每月區間首尾）、跨年（12/22、12/31、1/19）、閏年 2/29。

### 4.2 家族平衡
```
收集 [本命 monthId] + 所有守護靈 positions
對每個位置取 familyOf(pos)（月亮→家族；家族節點 5-8→自身；其餘 null）
計數 → {雷鳥,海龜,蝴蝶,青蛙}
主導 = 最大值家族；缺席 = 計數為 0 的家族（＝此生待學習課題）
```

### 4.3 相合（合盤）
```ts
function relate(a:Family,b:Family){
  const opp={雷鳥:'蝴蝶',蝴蝶:'雷鳥',海龜:'青蛙',青蛙:'海龜'};
  if(a===b) return '同族';
  if(opp[a]===b) return '雙合(對立)';
  return '半合(相鄰)';
}
```

### 4.4 盤面座標（前端繪製）
```
中心 (280,280)；pol(deg,r) = (280 + r·cos(deg-90°), 280 + r·sin(deg-90°))
外圈 16 節點：角度 = k·22.5°, k=0..15；k=0 北、4 東、8 南、12 西；月份夾其間
半徑：天群衛星 58 / 路徑 [154,119,84](外→內) / 外圈 196
中央衛星角度：7→0,8→51.43,2→102.86,3→154.29,4→205.71,5→257.14,6→308.57
路徑：每方位 spoke 角度 北0/東90/南180/西270；3 節點沿 R_PATH(外→內，號碼小在外)
markNode(id,color,text,offset): 於節點外圈畫 stroke 環，沿徑向外放「方位｜動物」標籤，多筆向下堆疊
合盤：A offset 0、B offset +5（同心雙環）
```
> 完整數值與 SVG 生成見原型 `medicine-wheel.html`（視為前端參考實作）。

### 4.5 落點驗證
- 守護靈 positions 僅接受 `1..36`（存在於 spec）。輸入字串以 `[,，、空白]` 分割、轉整數、過濾無效。

## 5. Supabase 資料庫 Schema

```sql
-- 規格資料（可選：也可純前端 spec.json，不入庫）
create table positions (
  id int primary key,                 -- 1..36
  layer text not null,                -- center/sky/family/direction/moon/path
  name text not null,
  date_start text, date_end text,     -- moon
  zodiac text, element text, family text, direction text,
  north_animal text, tw_animal text,
  path_dir text, path_name text,
  knowledge jsonb                     -- 知識卡內容
);

-- 使用者由 Supabase auth.users 提供
create table charts (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references auth.users(id) on delete cascade,
  type text not null check (type in ('personal','composite')),
  title text,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table chart_people (
  id uuid primary key default gen_random_uuid(),
  chart_id uuid not null references charts(id) on delete cascade,
  slot text not null check (slot in ('A','B')),
  nickname text,
  birth_month int, birth_day int,
  natal jsonb                          -- {monthId,familyNode,dirNode,...}
);

create table chart_guardians (
  id uuid primary key default gen_random_uuid(),
  person_id uuid not null references chart_people(id) on delete cascade,
  dir text not null check (dir in ('天','地','北','東','南','西')),
  animal text,
  positions int[] not null default '{}'
);

-- RLS：使用者只能存取自己的盤
alter table charts enable row level security;
create policy "own charts" on charts
  using (owner_id = auth.uid()) with check (owner_id = auth.uid());
-- chart_people / chart_guardians 透過 chart_id 連動同等政策（join 檢查）
```

## 7. API 合約（NestJS）

Base：`/api`。驗證：`Authorization: Bearer <supabase access token>`。

| Method | Path | 說明 | Body / 回傳 |
|---|---|---|---|
| GET | `/spec` | 取得藥輪規格（位置/月份/路徑） | → spec.json |
| GET | `/knowledge/:id` | 取得位置知識卡 | → `{id, entry}` |
| POST | `/compute/natal` | 生日算本命 | `{month,day}` → `Natal` |
| POST | `/compute/analyze` | 盤面家族平衡/相合 | `{people:PersonChart[],type}` → `{balance, relation?}` |
| GET | `/charts` | 我的盤列表 | → `Chart[]` |
| POST | `/charts` | 建立盤 | `Chart(no id)` → `Chart` |
| GET | `/charts/:id` | 取得單盤 | → `Chart` |
| PUT | `/charts/:id` | 更新盤 | `Chart` → `Chart` |
| DELETE | `/charts/:id` | 刪除盤 | → `204` |
| POST | `/charts/:id/report` | 產生解析報告(R2) | → `{rule, ai}` |
| POST | `/charts/:id/export` | 匯出圖(R3) | → `{url}` |

`/compute/*` 由 NestJS 轉呼 Python 服務（內部 `POST engine:8000/...`）。

## 8. Python 計算服務（FastAPI）
```
POST /natal      {month,day}                 → Natal
POST /balance    {positions:[...]}            → {雷鳥,海龜,蝴蝶,青蛙,dominant,absent}
POST /relate     {a:Family,b:Family}          → {type,desc}
POST /report     {chart}                      → {rule:str, ai:str}   # R2
```
- 純函式、無狀態；以 §6 spec 為輸入資料。
- `/report` 規則層由模板組裝；AI 層呼叫 LLM（system prompt 取自既有「藥輪分析師」設定，強調陪伴非預言、加免責）。
- pytest 金標：本命邊界/跨年/閏年、家族平衡、相合三類。

## 9. 前端（React + Tailwind）實作要點
- Vite + React + TypeScript；Tailwind theme 由《UIUX》§2 tokens 設定。
- 狀態：輕量（Zustand/Context）。`useWheelStore` 持有 `mode, activeKnowledgeId, people{A,B}, overlay`。
- `<WheelCanvas>`：依 spec 生成 SVG（節點層）＋ `<MarkerLayer>`（覆蓋層）。座標見 §4.4。
- 本命即時計算在前端（`lib/wheel/natal.ts`，與 Python 同邏輯、同 spec），體驗零延遲；儲存時以 Python 回傳為準。
- 訪客模式：localStorage 暫存（不可用瀏覽器儲存的環境則僅記憶體）；登入後寫入 Supabase。
- 既有 `medicine-wheel.html` 為視覺/互動 1:1 參考。

## 10. 部署與 CI/CD
- **前端**：GitHub → Vercel（PR preview、main → production）。環境變數 `VITE_SUPABASE_URL/ANON_KEY/API_BASE`。
- **NestJS**：容器化（Dockerfile）→ Render/Railway/Fly；環境變數 `SUPABASE_URL/SERVICE_ROLE/ENGINE_URL/JWT_SECRET`。
- **Python**：容器化 → 同上或獨立；`OPENAI/ANTHROPIC_API_KEY`（R2）。
- **Supabase**：migrations 以 `supabase db push`；seed 灌入 positions/knowledge。
- **CI（GitHub Actions）**：lint → typecheck → 前端單元 + Python pytest（金標）→ build → deploy。spec 一致性檢查（前端/Python 載入同檔雜湊比對）。
